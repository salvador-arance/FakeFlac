---
id: RP-11
title: Calibration and acceptance against a labelled local corpus
priority: high
milestone: H1
status: specified
---

`DetectionParams` are measured, and any proposed change is tuned, against a **labelled local corpus with known truth**, using the same Rust pipeline as the app (`fakeflac-audio` + `fakeflac-core`). The corpus has three sources of truth: lossless tracks the user trusts (negatives), lossy transcodes generated from them (positives) and fakes the user confirmed by hand. Tuning uses only the `tune` split; the figures reported for a proposal come from the `holdout` split. Nothing from the corpus enters the repository; only aggregate figures go into PRs (ADR-0022).

Acceptance criteria (each one is a scenario in `specs/features/calibration.feature` or an item of the local checklist in `specs/calibration/calibration.md`):

1. `just accept` with `FAKEFLAC_CORPUS` or `FAKEFLAC_CALIBRATION` unset exits with code 2 and a message naming the missing variable. It is not part of `just ci`.
2. On the sample corpus built from the synthetic fixtures (`specs/calibration/sample-corpus.md`), the confusion matrix equals the expected one exactly. This runs in CI without ffmpeg.
3. The `tune`/`holdout` split is assigned per album, is reproducible from the inputs alone, and every generated track has the split of its source.
4. A second run with no change decodes 0 files and transcodes 0 files.
5. The report contains the false-positive rate on trusted negatives by origin (primary figure from purchased or ripped origins only, with a 95 % confidence interval and a small-sample warning), the confusion matrix per encoder setting, and the margin of every track against every threshold.
6. Several parameter files are evaluated side by side in one run.
7. No absolute path, folder name or file name of the corpus appears in `summary.md`, the only report output allowed in a PR.

Source: phase 5 of `docs/planning/fakeflac-phases-1-3.es.md` (risk R3, H1 delivery criterion, section 2.7), ADR-0011, ADR-0022, ADR-0025, ADR-0036. Spec: `specs/calibration/`. Scenarios: `specs/features/calibration.feature` (tag `@RP-11`).
