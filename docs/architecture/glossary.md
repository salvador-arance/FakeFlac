# Glossary

> Terms used in specs and code. Spanish term in parentheses where the planning document uses it.

| Term (code) | Meaning |
|---|---|
| Cutoff (`cutoff`, corte) | Frequency above which a track has no real content, typically imposed by a lossy encoder's low-pass |
| Cliff (acantilado) | Sharp, sustained drop of spectral energy at the cutoff |
| Transcode (transcodificación) | Converting lossy audio to a lossless container (or to a higher bitrate) without recovering information |
| Fake / Suspicious / Real | Verdict relative to the *declared* quality of the file (ADR-0031) |
| Declared bitrate | Bitrate stored in a lossy file |
| Estimated source bitrate (`estimated_source_bitrate_kbps`, bitrate real) | Bitrate of the original the content actually corresponds to, estimated from the cutoff and other signals (RF-15) |
| Upsample | Raising bit depth or sample rate without adding information (RF-12, H3) |
| Average spectrum | Power-averaged FFT over sampled windows of a track |
| Leakage (fuga espectral) | Energy of strong components spreading into other bins because of the window |
| Window function | Weighting applied to a segment before the FFT (ADR-0025) |
| `DetectionParams` | Versioned data holding thresholds, window, overlap and cutoff→bitrate tables |
| `algorithm_version` | Integer bumped whenever results can change; part of the cache key |
| G1 / G2 | Human gates: approve spec/ADR; merge to `main` |
| Corpus | Real audio used for calibration and acceptance; lives outside the repo (`FAKEFLAC_CORPUS`) |
| Fixture | Synthetic audio generated by `just fixtures` |
